---
title: Forge Extension
description: Run Sentinel inside a Forge application, with its engine in the container, the HTTP API mounted and the dashboard contract registered.
---

The `extension` package adapts the engine as a `forge.Extension`. It loads `extensions.sentinel` from your config, picks a store, builds the engine, provides `*engine.Engine` in the DI container, mounts the HTTP API and registers the contract the Sentinel dashboard plugin reads.

## Registering the extension

```go
package main

import (
	"context"
	"log"

	"github.com/xraph/forge"

	sentinelext "github.com/xraph/sentinel/extension"
	"github.com/xraph/sentinel/target"
)

func main() {
	bot := target.FromFunc("support-bot", func(_ context.Context, input string) (string, error) {
		return "You can ask for a refund within 30 days.", nil
	})

	app := forge.NewApp(forge.AppConfig{
		Name:        "evals",
		HTTPAddress: ":8080",
		Extensions: []forge.Extension{
			sentinelext.New(
				sentinelext.WithTarget("support-bot", "The support assistant in staging", bot),
			),
		},
	})

	if err := app.Run(); err != nil {
		log.Fatal(err)
	}
}
```

`app.RegisterExtension(ext)` works too, if you'd rather build the extension after the app.

That example has no store of its own. The extension takes one from a `*grove.DB` in the container, which the Grove extension provides. If nothing provides one, the engine has no store, `Health` reports `sentinel: no store configured`, and every call returns `sentinel.ErrNoStore`. There's no in-memory fallback. To pass a store yourself:

```go
sentinelext.New(
	sentinelext.WithStore(memory.New()),
)
```

## What the extension does

| Phase | What happens |
|-------|--------------|
| `Register` | Loads config, resolves the store, builds the engine from the merged config plus your engine options, mounts the HTTP API under `base_path` (default `/sentinel`) unless routes are disabled, and provides `*engine.Engine` in the container |
| `Start` | Runs `Migrate` on the store unless migrations are disabled, then `engine.Start` |
| `Health` | Pings the store |
| `Stop` | Calls `engine.Stop`: cancels runs this process started with `StartRun`, waits up to `shutdown_timeout` for them to record it, fires `OnShutdown`, then closes the store |

It also implements Forge's dashboard contract contributor hook, so the dashboard plugin finds it without any wiring from you (see [Dashboard](#dashboard)).

## Extension options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `WithStore(s)` | `store.Store` | none | The store to use. A grove database in the container overrides it, see [Store resolution](#store-resolution) |
| `WithGroveDatabase(name)` | `string` | `""` | Resolve the named `*grove.DB` from the container. An empty name means the default one |
| `WithExtension(x)` | `plugin.Extension` | none | A lifecycle hook plugin (repeatable) |
| `WithTarget(name, description, t)` | `string, string, target.Target` | none | Register a named target, so the dashboard can start runs against it (repeatable) |
| `WithScorer(d, f)` | `scorer.Descriptor, scorer.Factory` | none | Register a scorer by name, such as an LLM scorer that needs your client (repeatable) |
| `WithEngineOption(opt)` | `engine.Option` | none | Pass any engine option through |
| `WithConfig(cfg)` | `extension.Config` | defaults | Replace the whole config struct |
| `WithBasePath(path)` | `string` | `/sentinel` | URL prefix for the HTTP API |
| `WithDisableRoutes()` | none | off | Don't mount the HTTP API |
| `WithDisableMigrate()` | none | off | Don't run migrations on `Start` |
| `WithRequireConfig(b)` | `bool` | `false` | Fail `Register` when the config file has no sentinel block |

## Configuration

The extension reads `extensions.sentinel`, and falls back to a top-level `sentinel` key:

```yaml
# config.yaml
extensions:
  sentinel:
    base_path: "/sentinel"
    default_model: "smart"
    temperature: 0
    pass_threshold: 0.7
    regression_threshold: 0.05
    concurrency: 4
    shutdown_timeout: "30s"
    grove_database: ""
    dashboard_app_id: "app_yourapp"
    disable_routes: false
    disable_migrate: false
```

| YAML key | Type | Default | Description |
|----------|------|---------|-------------|
| `base_path` | `string` | `/sentinel` | URL prefix for the HTTP API. Empty means `/sentinel` |
| `default_model` | `string` | `"smart"` | The model for suites that don't set one. Sentinel passes it to your client as is |
| `temperature` | `float64` | `0` | Temperature for suites that don't set one |
| `pass_threshold` | `float64` | `0.7` | Minimum average score for a case to pass |
| `regression_threshold` | `float64` | `0.05` | How far a metric may fall below the current baseline before a run counts as regressed |
| `concurrency` | `int` | `4` | Cases evaluated in parallel |
| `shutdown_timeout` | `duration` | `"30s"` | How long `Stop` waits for in-flight runs |
| `grove_database` | `string` | `""` | A named `*grove.DB` from the container. Setting it turns on grove resolution |
| `dashboard_app_id` | `string` | none | The app the dashboard reads and writes when the principal has no `app_id` claim. With neither, every dashboard request is refused |
| `disable_routes` | `bool` | `false` | Don't mount the HTTP API |
| `disable_migrate` | `bool` | `false` | Don't run migrations on `Start` |

When a config block exists, its values win, then your programmatic options fill what it left empty, then the defaults. Programmatic `WithDisableRoutes` and `WithDisableMigrate` always win when set. A zero `pass_threshold`, `regression_threshold`, `concurrency` or `shutdown_timeout` counts as unset. `temperature` is the exception: with a config block present, its value is used even when it's 0, and a programmatic temperature is ignored.

To insist on a config block:

```go
sentinelext.New(
	sentinelext.WithRequireConfig(true),
)
```

## Store resolution

The extension decides on a store during `Register`:

1. If `WithGroveDatabase` was called or `grove_database` is set, it resolves that `*grove.DB` (the default one for an empty name) and fails `Register` if it isn't there.
2. Otherwise, if the container has a default `*grove.DB`, it uses that.
3. Otherwise it uses the store you passed with `WithStore`, if any.

In the first two cases it builds the store from the driver name: `pg` gives `store/postgres`, `sqlite` gives `store/sqlite` and `mongo` gives `store/mongo`. Any other driver fails `Register`. Note the order: a grove database found in steps 1 or 2 replaces a store you passed with `WithStore`, so don't combine the two.

```go
sentinelext.New(
	sentinelext.WithGroveDatabase("evals"), // a named grove.DB
)
```

For a SQLite database you build yourself, remember the migration executor import described on the [SQLite page](/docs/infrastructure/sqlite).

## Using the engine elsewhere

The engine is in the container once `Register` has run:

```go
eng, err := forge.Inject[*engine.Engine](app.Container())
if err != nil {
	log.Fatal(err)
}
```

The extension value also has `Engine()`, which returns nil before `Register`.

## Dashboard

Sentinel's dashboard is the `@forge-go/dashboard-plugin-sentinel` plugin for the Forge dashboard's React shell. Add it to your shell's plugin list and the pages mount at `/@sentinel`. The extension registers the contract the plugin reads on its own, so there's nothing to wire in Go.

You do need to tell Sentinel which app the dashboard works in:

```yaml
extensions:
  sentinel:
    dashboard_app_id: app_yourapp
```

The dashboard takes the app from the signed-in principal's `app_id` claim first. Nothing sets that claim yet, so today it comes from `dashboard_app_id`. There's no default. With neither, every dashboard request is refused, because an empty app id would match every app's suites and runs.

To start runs from the dashboard, register at least one target. Scorers that need your application's LLM client go in the same way:

```go
ext := sentinelext.New(
	sentinelext.WithTarget("support-bot", "The support assistant under test", myTarget),
	sentinelext.WithScorer(scorer.Descriptor{
		Name:      "judge",
		Dimension: "persona",
		UsesLLM:   true,
	}, judgeFactory),
)
```

With no target registered, the dashboard says so and points you at its Setup page instead of offering a Start button.

## The HTTP API

The routes mount under `base_path` plus `/v1`, so `/sentinel/v1/...` by default. Not all of them work yet: some are stubs and, against Forge v1.12.7, most of the list and command routes fail to register at all. The [HTTP API reference](/docs/api-reference/http-api) lists which ones you can call. Start runs from Go or from the dashboard.

## Setting the app on requests

The API reads the app from the request context in two places: `POST /v1/suites` stamps it on the new suite, and `GET /v1/suites` filters by it. Nothing else in the API reads it. To set it, add a Forge middleware before `app.Run`:

```go
app.Router().Use(func(next forge.Handler) forge.Handler {
	return func(c forge.Context) error {
		// Take the app from your own auth, not from a header the caller controls.
		appID := c.Header("X-App-ID")
		c.WithContext(sentinel.WithApp(c.Context(), appID))
		return next(c)
	}
})
```

## Adding metrics

The observability plugin takes Forge's metrics as its factory. Build the extension after the app so you can pass `app.Metrics()`:

```go
app := forge.NewApp(forge.AppConfig{Name: "evals"})

ext := sentinelext.New(
	sentinelext.WithExtension(observability.NewMetricsExtensionWithFactory(app.Metrics())),
)
if err := app.RegisterExtension(ext); err != nil {
	log.Fatal(err)
}
```
