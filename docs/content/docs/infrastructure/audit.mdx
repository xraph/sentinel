---
title: Audit Trail
description: Bridge evaluation lifecycle events to an audit backend for compliance and debugging.
---

The `audit_hook` package bridges Sentinel lifecycle events to an audit trail backend. It records structured audit events for evaluation operations.

## Setup

```go
import audithook "github.com/xraph/sentinel/audit_hook"

// With a Recorder implementation
auditExt := audithook.New(myRecorder)

// Or with a simple function
auditExt = audithook.New(audithook.RecorderFunc(func(ctx context.Context, event *audithook.AuditEvent) error {
    log.Printf("AUDIT: %s %s %s", event.Action, event.Resource, event.ResourceID)
    return nil
}))

// Register with engine
eng, err := engine.New(
    engine.WithStore(st),
    engine.WithExtension(auditExt),
)
```

The directory is `audit_hook` and the package name is `audithook`, so name the import. `AuditEvent` mirrors Chronicle's audit event field for field without importing Chronicle, so wiring it to [Chronicle](https://github.com/xraph/chronicle) takes a small `RecorderFunc` that copies the fields across. If `Record` returns an error, the extension logs it (set the logger with `audithook.WithLogger`) and the run carries on.

## Recorder interface

```go
type Recorder interface {
    Record(ctx context.Context, event *AuditEvent) error
}
```

The `RecorderFunc` adapter lets you use a plain function:

```go
type RecorderFunc func(ctx context.Context, event *AuditEvent) error
```

## AuditEvent

```go
type AuditEvent struct {
    Action     string
    Resource   string
    Category   string
    ResourceID string
    Metadata   map[string]any
    Outcome    string
    Severity   string
    Reason     string
}
```

## Actions

| Action | Severity | Outcome |
|--------|----------|---------|
| `sentinel.eval.run.started` | info | success |
| `sentinel.eval.run.completed` | info | success |
| `sentinel.eval.run.failed` | critical | failure |
| `sentinel.case.completed` | info | success |
| `sentinel.case.failed` | critical | failure |
| `sentinel.regression.detected` | warning | failure |
| `sentinel.baseline.saved` | info | success |
| `sentinel.persona.eval.started` | info | success |
| `sentinel.persona.eval.completed` | info | success |
| `sentinel.prompt.version.created` | info | success |
| `sentinel.comparison.completed` | info | success |
| `sentinel.redteam.started` | info | success |
| `sentinel.redteam.completed` | info | success |

Each has an `audithook.Action...` constant. The two red-team actions never occur today, because their hooks aren't fired. There's no case-started action.

## Severity levels

| Level | Usage |
|-------|-------|
| `info` | Normal operations (run started, case completed) |
| `warning` | Regression detected |
| `critical` | Run failed, case target error |

## Filtering

Use `WithActions` to limit which events are recorded:

```go
auditExt := audithook.New(myRecorder,
    audithook.WithActions(
        audithook.ActionEvalRunStarted,
        audithook.ActionEvalRunFailed,
        audithook.ActionRegressionDetected,
    ),
)
```

Only the specified actions will be recorded; all others are silently dropped.
