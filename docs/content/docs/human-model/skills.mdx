---
title: Skill Evaluation
description: Check which tools an agent used, against the ones it should and shouldn't have.
---

Skill evaluation checks whether an agent reached for the right tools. It reads the tool calls in the run trace, so the target has to return one (see [Traces](/docs/human-model/overview#traces)).

## Scorer: `skill_usage`

```go
s := scorer.NewSkillUsageScorer(
	[]string{"search_orders", "issue_refund"}, // expected
	[]string{"delete_account"},                // forbidden
)
```

The score is the share of expected tools that appear in `Trace.ToolCalls`, matched by `ToolName`. With no expected tools it starts at 1.0. Each forbidden tool that was called takes 0.3 off, down to 0. Order, arguments and tool errors aren't checked. Without a trace the score is 0.

`Details` lists `used_tools`, `missing_tools` and `forbidden_used`, and the reason reads like `used 1/2 expected tools; missing: issue_refund`.

The scorer isn't in the registry by default. To name it on a case, register a factory as shown in the [overview](/docs/human-model/overview#using-the-scorers).

## Scenario: `skill_challenge`

`scenario.NewSkillChallengeGenerator(tools)` writes one case per tool, up to `Count` (default 3). Each asks the agent to use that tool, names `skill_usage` with `expected_tools` set to that one tool, and puts `target_tool` and `difficulty` in its `Context`:

```go
gen := scenario.NewSkillChallengeGenerator([]string{"search_code", "read_file", "run_tests"})
cases, err := gen.Generate(ctx, &scenario.GenerateConfig{SuiteID: suiteID.String(), Difficulty: "medium"})
```

## Dimension score

```go
result.DimensionScores["skill"] // 0.0 to 1.0
```

`sentineltest.SkillProficiency(min)` asserts on it.

## Use cases

- Check that a support agent looks the order up before it issues a refund tool call
- Make sure an agent never calls a destructive tool in a read-only scenario
- Catch a prompt change that stops the agent using its search tool
