---
title: Cognitive Evaluation
description: Check that an agent's trace steps go through the phases you expect, in order.
---

Cognitive evaluation checks how an agent worked through a problem: did it analyse before it planned, and plan before it acted. It reads the steps in the run trace, so the target has to return one (see [Traces](/docs/human-model/overview#traces)).

## Scorer: `cognitive_phase`

```go
s := scorer.NewCognitivePhaseScorer([]string{"analysis", "planning", "execution", "verification"})
```

The scorer walks `Trace.Steps` in order and matches each step's `Type` against the next expected phase, exactly and case-sensitively. The score is how many phases it matched, divided by the number expected. Extra steps in between don't hurt. With no expected phases the score is 1. Without a trace it's 0.

Phase names are whatever your agent writes into `StepTrace.Type`. Sentinel has no fixed list.

The scorer isn't in the registry by default. To name it on a case, register a factory as shown in the [overview](/docs/human-model/overview#using-the-scorers).

## Scenario: `cognitive_stress`

`scenario.NewCognitiveStressGenerator(phases)` writes up to three cases at rising difficulty (a simple question, a multi-step budget problem, a system design problem). Each names `cognitive_phase` with `expected_phases` and puts `stress_level` in its `Context`:

```go
gen := scenario.NewCognitiveStressGenerator([]string{"analysis", "planning", "execution"})
cases, err := gen.Generate(ctx, &scenario.GenerateConfig{SuiteID: suiteID.String()})
```

## Dimension score

```go
result.DimensionScores["cognition"] // 0.0 to 1.0
```

`sentineltest.CognitivePhaseCompliance(min)` asserts on it.

## Use cases

- Check that a reviewer agent analyses before it starts suggesting fixes
- Catch an agent that skips verification after a prompt change
