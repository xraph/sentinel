---
title: Trait Evaluation
description: Ask a judge model whether an agent's answer shows a given personality trait.
---

Trait evaluation checks whether an answer shows a personality trait you describe, such as thoroughness or patience. A judge model does the checking, so you need an LLM client.

## Scorer: `trait_consistency`

```go
s := scorer.NewTraitConsistencyScorer(client, "gpt-4o-mini",
	"thoroughness", "Checks edge cases and explains the reasoning behind each finding")
```

`client` is a `scorer.LLMClient`. The scorer sends the trait name, its description, the case input and the answer to the judge at temperature 0 and asks for a JSON score from 0 to 1 with a reason. It looks at one answer at a time: consistency across cases comes from running several cases (or the trait probe scenario) and comparing their scores, not from the scorer itself. A client error makes the case `error`.

The scorer isn't in the registry by default. To name it on a case, register a factory as shown in the [overview](/docs/human-model/overview#using-the-scorers).

## Scenario: `trait_probe`

`scenario.NewTraitProbeGenerator(name, desc)` writes up to three cases that probe the trait in different situations: under normal conditions, when challenged, and on a complex request. Each names `trait_consistency` with `trait_name` and `trait_desc`:

```go
gen := scenario.NewTraitProbeGenerator("thoroughness", "Checks edge cases")
cases, err := gen.Generate(ctx, &scenario.GenerateConfig{SuiteID: suiteID.String()})
```

## Dimension score

```go
result.DimensionScores["trait"] // 0.0 to 1.0
```

`sentineltest.TraitConsistency(min)` asserts on it.

## Use cases

- Check that a careful reviewer agent keeps flagging risks after a prompt rewrite
- Compare how two prompt versions hold a persona's patience under pushback
