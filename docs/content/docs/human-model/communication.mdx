---
title: Communication Evaluation
description: Ask a judge model whether an answer's tone and format match what you expect.
---

Communication evaluation checks how an agent talks: the tone and the shape of the answer. A judge model does the checking, so you need an LLM client.

## Scorer: `communication_style`

```go
s := scorer.NewCommunicationStyleScorer(client, "gpt-4o-mini", "friendly, plain language", "short paragraphs")
```

`client` is a `scorer.LLMClient`. Tone and format are free-text descriptions. The scorer sends them, the case input and the answer to the judge at temperature 0 and asks for a JSON score from 0 to 1 with a reason. There are no numeric formality, verbosity or technical-level settings; put whatever you care about into the two descriptions. A client error makes the case `error`.

The scorer isn't in the registry by default. To name it on a case, register a factory as shown in the [overview](/docs/human-model/overview#using-the-scorers).

## Scenario: `comms_adaptation`

`scenario.NewCommsAdaptationGenerator(audiences)` writes one case per audience, up to `Count` (default: all of them). Each names `communication_style` with that audience's `expected_tone` and `expected_format`:

```go
gen := scenario.NewCommsAdaptationGenerator([]scenario.Audience{
	{Name: "junior developer", Description: "New to the codebase", ExpectedTone: "friendly", ExpectedFormat: "step by step"},
	{Name: "staff engineer", Description: "Knows the system well", ExpectedTone: "direct", ExpectedFormat: "terse bullet points"},
})
cases, err := gen.Generate(ctx, &scenario.GenerateConfig{SuiteID: suiteID.String()})
```

## Dimension score

```go
result.DimensionScores["communication"] // 0.0 to 1.0
```

`sentineltest.CommunicationMatch(min)` asserts on it.

## Use cases

- Check that a support agent keeps jargon out of answers for end users
- Make sure an internal tool answers experts briefly
