---
title: Perception Evaluation
description: Check that an answer mentions what matters and doesn't dwell on distractors.
---

Perception evaluation checks what an agent noticed. Given input with something important buried among noise, does the answer talk about the important part? It works on the answer text alone, so any target will do.

## Scorer: `perception_focus`

```go
s := scorer.NewPerceptionFocusScorer(
	[]string{"SQL injection"},      // required
	[]string{"formatting", "typo"}, // distractors
)
```

The score is the share of required keywords found in the answer (case-insensitive substring). With none required it starts at 1. Each distractor that appears costs up to 0.3 in total, spread evenly over the distractors you listed, so mentioning all of them takes 0.3 off.

`Details` lists `missing_keywords` and `focused_distractors`.

The scorer isn't in the registry by default. To name it on a case, register a factory as shown in the [overview](/docs/human-model/overview#using-the-scorers).

## Scenario: `perception_test`

`scenario.NewPerceptionGenerator(relevant, distractors)` writes a case that lists the relevant topics and asks for a summary and, when `Count` is 2 or more (the default), a second that names the distractors too and tells the agent to leave them out. Both name `perception_focus` with `required_keywords` and `ignored_keywords`:

```go
gen := scenario.NewPerceptionGenerator([]string{"SQL injection"}, []string{"formatting", "typo"})
cases, err := gen.Generate(ctx, &scenario.GenerateConfig{SuiteID: suiteID.String()})
```

## Dimension score

```go
result.DimensionScores["perception"] // 0.0 to 1.0
```

`sentineltest` has no perception assertion. Check `res.Stats.DimensionScores["perception"]` yourself, or write an `AssertCheck`.

## Use cases

- Check that a security reviewer leads with the vulnerability, not the style nits
- Make sure a triage agent picks the outage out of a noisy incident report
