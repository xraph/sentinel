---
title: Multi-Tenancy
description: How the app ID on a context labels suites and runs, what filters by it, and what doesn't.
---

Suites and runs carry an `AppID`. You set it through the context, and list calls can filter by it. That's the extent of it today: Sentinel labels and filters by app, it doesn't enforce isolation. If one process serves several apps or customers, keep the checks in your own code.

## Context helpers

```go
import "github.com/xraph/sentinel"

ctx = sentinel.WithApp(ctx, "myapp")
ctx = sentinel.WithTenant(ctx, "org-123")

appID    := sentinel.AppFromContext(ctx)    // "myapp"
tenantID := sentinel.TenantFromContext(ctx) // "org-123"
```

Both readers return an empty string when nothing is set.

## What reads the app

| Where | What it does with the app |
|-------|---------------------------|
| `engine.CreateSuite` | Stamps `AppID` from the context when the suite doesn't have one |
| Runs | Take the suite's `AppID` when they're created |
| `suite.ListFilter{AppID}`, `evalrun.ListFilter{AppID}` | Filter lists. An empty `AppID` matches every app |
| `GetSuiteByName(ctx, appID, name)` | Looks up a name within one app. Names are unique per app |
| HTTP API | `POST /v1/suites` stamps the app from the request context, and `GET /v1/suites` filters by it |
| Dashboard | Uses the principal's `app_id` claim, else `dashboard_app_id`, and refuses every request when both are empty |

Cases, baselines and prompt versions have no app of their own. They belong to a suite.

## What doesn't

Lookups by ID (`GetSuite`, `GetRun`, `GetCase`, `GetBaseline` and the rest) ignore the context, so anyone holding an ID can read the entity whatever app it belongs to. The same goes for the HTTP routes that take an ID. `TenantFromContext` isn't called anywhere in Sentinel, and `Run.TargetTenantID` exists on the model but nothing sets it.

## Example

```go
ctxA := sentinel.WithApp(context.Background(), "app-a")
_ = eng.CreateSuite(ctxA, suiteA) // suiteA.AppID == "app-a"

ctxB := sentinel.WithApp(context.Background(), "app-b")
_ = eng.CreateSuite(ctxB, suiteB) // suiteB.AppID == "app-b"

onlyA, _ := eng.ListSuites(ctxA, &suite.ListFilter{AppID: "app-a"})
everything, _ := eng.ListSuites(ctxA, &suite.ListFilter{}) // empty AppID: every app
```

`ListSuites` filters on the `AppID` in the filter you pass, not on the context.

## In a Forge app

Set the app on each request with a middleware, from your own auth rather than a header the caller controls. The [Forge guide](/docs/guides/forge-extension#setting-the-app-on-requests) has an example.
