## Engine configuration

`sentinel.Config` holds the engine's defaults:

```go
type Config struct {
    DefaultModel        string        // model for suites that don't set one (default: "smart")
    Temperature         float64       // temperature for suites that don't set one (default: 0)
    PassThreshold       float64       // minimum average score for a case to pass (default: 0.7)
    RegressionThreshold float64       // how far a metric may fall below the baseline (default: 0.05)
    Concurrency         int           // cases evaluated in parallel (default: 4)
    ShutdownTimeout     time.Duration // how long Stop waits for in-flight runs (default: 30s)
}
```

`engine.New` starts from `sentinel.DefaultConfig()`, which returns exactly those defaults.

Sentinel doesn't resolve `"smart"` or `"fast"` to anything. The model name is a string it hands to your target's client, so your client decides what `"smart"` means.

### Overriding defaults

`engine.WithConfig` replaces the whole struct, so start from the defaults and change what you need:

```go
cfg := sentinel.DefaultConfig()
cfg.DefaultModel = "gpt-4o"
cfg.PassThreshold = 0.8
cfg.Concurrency = 8

eng, err := engine.New(
    engine.WithStore(pgStore),
    engine.WithConfig(cfg),
)
```

A struct literal with only a few fields leaves the rest at zero, and the engine takes those zeros at face value: a zero `RegressionThreshold` makes any drop at all a regression, and a zero `Concurrency` runs one case at a time.

## Engine options

| Option | Description |
|--------|-------------|
| `engine.WithStore(s)` | Sets the store. Without one, every engine call returns `sentinel.ErrNoStore` |
| `engine.WithConfig(cfg)` | Replaces the configuration |
| `engine.WithExtension(ext)` | Registers a plugin (lifecycle hooks) |
| `engine.WithLogger(l)` | Sets the logger, a go-utils `log.Logger`. The default is a no-op logger |
| `engine.WithMetrics(m)` | Records run, case, target and scorer metrics on a go-utils `metrics.Metrics`. The default records none. The Forge extension passes `app.Metrics()` for you, see [Observability](/docs/infrastructure/observability) |
| `engine.WithTarget(name, description, t)` | Registers a target by name, for `StartRun` and the dashboard |
| `engine.WithScorer(d, f)` | Registers a scorer factory by name, so cases and `StartRun` can use it |

## Suite-level overrides

A suite can set its own model and temperature:

```go
s := &suite.Suite{
    Model:       "claude-3-opus", // overrides DefaultModel
    Temperature: 0.3,             // overrides Temperature
}
```

`CreateSuite` fills an empty `Model` with `DefaultModel` at the time you create it. A run uses `RunConfig.Model` if you set one, then the suite's model. A suite temperature of 0 counts as unset, so a suite can't pin 0 over a non-zero default.

## Forge extension options

The `extension.New` function takes its own options:

```go
ext := extension.New(
    extension.WithStore(pgStore),
    extension.WithExtension(metricsPlugin),
    extension.WithDisableRoutes(),
    extension.WithDisableMigrate(),
    extension.WithBasePath("/sentinel"),
)
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `WithStore(s)` | `store.Store` | none | The store. A grove database in the container overrides it, see the [Forge guide](/docs/guides/forge-extension#store-resolution) |
| `WithExtension(x)` | `plugin.Extension` | none | Lifecycle hook plugin (repeatable) |
| `WithEngineOption(opt)` | `engine.Option` | none | Pass an engine option through |
| `WithConfig(cfg)` | `extension.Config` | defaults | The full config struct |
| `WithDisableRoutes()` | none | off | Skip HTTP route registration |
| `WithDisableMigrate()` | none | off | Skip migrations on Start |
| `WithBasePath(path)` | `string` | `/sentinel` | URL prefix for the HTTP API |
| `WithGroveDatabase(name)` | `string` | `""` | Resolve this `*grove.DB` from the container. Empty means the default one |
| `WithRequireConfig(b)` | `bool` | `false` | Require a sentinel block in the config file |
| `WithTarget(name, description, t)` | `string, string, target.Target` | none | Register a named target, so the dashboard can start runs against it (repeatable) |
| `WithScorer(d, f)` | `scorer.Descriptor, scorer.Factory` | none | Register a scorer the dashboard can offer, such as an LLM scorer that needs your client (repeatable) |

The extension builds the engine with `engine.WithConfig` from its own merged config and `engine.WithMetrics(app.Metrics())` first, then applies your `WithEngineOption` values, so an `engine.WithConfig` or `engine.WithMetrics` you pass through still wins.

## Dashboard

Sentinel's dashboard is the `@forge-go/dashboard-plugin-sentinel` plugin for the Forge dashboard's React shell. Add it to your shell's plugin list and the pages mount at `/@sentinel`. The extension registers the contract the plugin reads on its own, so there's nothing to wire in Go.

You do need to tell Sentinel which app the dashboard works in:

```yaml
extensions:
  sentinel:
    dashboard_app_id: app_yourapp
```

The dashboard takes the app from the signed-in principal's `app_id` claim first. Nothing sets that claim yet, so today it comes from `dashboard_app_id`. There's no default. With neither, every dashboard request is refused, because an empty app id would match every app's suites and runs.

To start runs from the dashboard, register at least one target. Scorers that need your application's LLM client go in the same way:

```go
ext := extension.New(
    extension.WithTarget("support-bot", "The support assistant under test", myTarget),
    extension.WithScorer(scorer.Descriptor{
        Name:      "judge",
        Dimension: "persona",
        UsesLLM:   true,
    }, judgeFactory),
)
```

With no target registered, the dashboard says so and points you at its Setup page instead of offering a Start button.

## File-based configuration (YAML)

When running as a Forge extension, Sentinel loads its configuration from your config files. It looks under these keys, in order:

1. `extensions.sentinel`, the standard Forge extension namespace
2. `sentinel`, a top-level shorthand

### Example

```yaml
# config.yaml
extensions:
  sentinel:
    disable_routes: false
    disable_migrate: false
    base_path: "/sentinel"
    default_model: "smart"
    temperature: 0
    pass_threshold: 0.7
    regression_threshold: 0.05
    concurrency: 4
    shutdown_timeout: "30s"
    grove_database: ""
    dashboard_app_id: "app_yourapp"
```

### Config fields

| YAML Key | Type | Default | Description |
|----------|------|---------|-------------|
| `disable_routes` | `bool` | `false` | Skip HTTP route registration |
| `disable_migrate` | `bool` | `false` | Skip migrations on Start |
| `base_path` | `string` | `/sentinel` | URL prefix for all routes. Empty means `/sentinel` |
| `default_model` | `string` | `"smart"` | Model for suites that don't set one |
| `temperature` | `float64` | `0` | Temperature for suites that don't set one |
| `pass_threshold` | `float64` | `0.7` | Minimum score to pass |
| `regression_threshold` | `float64` | `0.05` | How far a metric may fall below the current baseline before a run counts as regressed |
| `concurrency` | `int` | `4` | Cases evaluated in parallel |
| `shutdown_timeout` | `duration` | `"30s"` | Max graceful shutdown wait |
| `grove_database` | `string` | `""` | Named `*grove.DB` from the container |
| `dashboard_app_id` | `string` | none | The app the dashboard reads and writes when the principal has no `app_id` claim. With neither, every dashboard request is refused. |

### Merge behaviour

File-based configuration is merged with programmatic options. Programmatic boolean flags (`DisableRoutes`, `DisableMigrate`) always win when set to `true`. For other fields, YAML values take precedence, then programmatic values, then defaults.

A zero `pass_threshold`, `regression_threshold`, `concurrency` or `shutdown_timeout` counts as unset, so it falls back to the next source and then to the default. If you want any drop at all to count as a regression, set `regression_threshold` to a very small value such as `0.0001`. `temperature` is different: when a config block exists, its value is used as is, 0 included, and a programmatic temperature is ignored.
