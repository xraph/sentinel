Everything is in one module, `github.com/xraph/sentinel`. The full API is on [pkg.go.dev](https://pkg.go.dev/github.com/xraph/sentinel).

## Core packages

### `github.com/xraph/sentinel`

Root package: context helpers, config, errors and shared types.

| Export | Description |
|--------|-------------|
| `WithApp(ctx, id)`, `AppFromContext(ctx)` | Put an app ID on a context and read it back |
| `WithTenant(ctx, id)`, `TenantFromContext(ctx)` | The same for a tenant ID, which nothing in Sentinel reads yet |
| `Config`, `DefaultConfig()` | Engine configuration and its defaults |
| `Entity`, `NewEntity()` | Base type with `CreatedAt` and `UpdatedAt` |
| `ID`, `Prefix` | Aliases of `id.ID` and `id.Prefix` |
| `ErrNoStore`, `ErrStoreClosed`, `ErrMigrationFailed` | Store errors |
| `ErrSuiteNotFound`, `ErrCaseNotFound`, `ErrRunNotFound`, `ErrBaselineNotFound`, `ErrPromptVersionNotFound` | Not-found errors |
| `ErrSuiteAlreadyExists`, `ErrPromptVersionExists` | Conflict errors |
| `ErrInvalidState`, `ErrRunCancelled`, `ErrEmptyInput`, `ErrInvalidInput`, `ErrUnsupportedFormat` | State and input errors |
| `ErrNoTarget`, `ErrNoScorers`, `ErrUnknownTarget`, `ErrUnknownScorer` | Evaluation errors |

See [Error Handling](/docs/concepts/errors) for when each one comes back.

### `github.com/xraph/sentinel/engine`

The coordinator.

| Export | Description |
|--------|-------------|
| `New(...Option) (*Engine, error)` | Create an engine |
| `WithStore`, `WithConfig`, `WithExtension`, `WithLogger`, `WithTarget`, `WithScorer` | Options |
| `RunConfig`, `RunResult`, `StartConfig`, `RegisteredTarget` | Run inputs and outputs |
| `Engine.RunEval(ctx, *RunConfig)` | Run a suite synchronously with target and scorer values |
| `Engine.StartRun(ctx, *StartConfig)` | Start a run by registered names and return at once |
| `Engine.CancelRun(ctx, runID)` | Ask a running run to stop |
| `Engine.GenerateRedTeam(ctx, suiteID, types, count)` | Write attack cases into a suite |
| `Engine.ImportCases(ctx, suiteID, format, data)` | Parse JSON, CSV or JSONL and write the cases |
| `Engine.CreateSuite`, `GetSuite`, `GetSuiteByName`, `ListSuites`, `UpdateSuite`, `DeleteSuite` | Suites |
| `Engine.CreateCase`, `CreateCaseBatch`, `GetCase`, `UpdateCase`, `DeleteCase`, `ListCases`, `CountCases` | Cases |
| `Engine.GetRun`, `ListRuns`, `ListRunsBySuite`, `ListResults`, `GetResultStats` | Runs and results |
| `Engine.SaveBaseline`, `GetBaseline`, `GetLatestBaseline`, `ListBaselines`, `DeleteBaseline` | Baselines |
| `Engine.CreatePromptVersion`, `GetPromptVersion`, `ListPromptVersions`, `GetCurrentPromptVersion`, `SetCurrentPromptVersion` | Prompt versions |
| `Engine.Targets()`, `Target(name)`, `Scorers()` | Registered targets and the scorer registry |
| `Engine.Start(ctx)`, `Stop(ctx)`, `Health(ctx)` | Lifecycle. `Start` does nothing yet; `Stop` cancels runs and closes the store |
| `Engine.Store()`, `Config()`, `Logger()`, `Extensions()` | Accessors |

`PromptVersion` and the store interface.

## Evaluation packages

### `github.com/xraph/sentinel/scorer`

The `Scorer` interface, `Input`, `Output`, the `Registry` with `Descriptor` and `Factory`, `LLMClient` and `EmbeddingClient`, and 20 built-in scorers plus `FromFunc`.

**Deterministic:** `ExactScorer`, `ContainsScorer`, `NotContainsScorer`, `NewRegexScorer`, `JSONValidScorer`, `JSONSchemaScorer` (checks JSON validity only; the schema isn't enforced yet), `LengthScorer` (word count), `LatencyScorer`, `CostScorer`

**Model-graded:** `NewLLMJudgeScorer`, `NewFactualScorer`, `NewHallucinationScorer`, `NewSemanticScorer`

**Agent:** `NewSkillUsageScorer`, `NewTraitConsistencyScorer`, `NewBehaviorTriggerScorer`, `NewCognitivePhaseScorer`, `NewCommunicationStyleScorer`, `NewPerceptionFocusScorer`, `NewPersonaCoherenceScorer`

The registry knows only the nine deterministic names (`exact`, `contains`, `not_contains`, `regex`, `json_valid`, `json_schema`, `length`, `latency`, `cost`) until you add more with `engine.WithScorer`.

### `github.com/xraph/sentinel/target`

| Export | Description |
|--------|-------------|
| `Target`, `Output` | The interface (`Name()`, `Call(ctx, input)`) and what a call returns |
| `FromFunc(name, fn)` | Wrap a plain function |
| `NewLLMTarget(client, model, systemPrompt, temperature)` | One LLM call through your `LLMClient` |
| `NewAgentTarget(client, agentID, personaRef)` | An agent call through your `AgentClient`, with its trace |
| `CallOptions`, `CallOptionsFrom(ctx)`, `WithCallOptions` | The prompt, model and temperature a run passes to its target |

### `github.com/xraph/sentinel/scenario`

Six generators: `NewSkillChallengeGenerator`, `NewTraitProbeGenerator`, `NewBehaviorTriggerGenerator`, `NewCognitiveStressGenerator`, `NewCommsAdaptationGenerator`, `NewPerceptionGenerator`, with `GenerateConfig` and `Audience`.

### `github.com/xraph/sentinel/redteam`

Five generators (injection, jailbreak, leakage, hallucination, off-topic), `AttackType` constants, `GeneratorFor`, `MaxPerType`. The `Report` and `Config` types aren't used by anything yet.

### `github.com/xraph/sentinel/comparison`

`Compare` runs a suite against several targets, `FormatTable` prints the result, and `Diff` gives deltas between two `ResultStats`.

### `github.com/xraph/sentinel/dataset`

`LoadJSON`, `LoadCSV`, `LoadJSONL`, `ToCases`, `Sample`, and `NewLLMGenerator` for model-written cases.

### `github.com/xraph/sentinel/report`

`NewReport`, and the terminal, JSON, HTML and CI (GitHub Actions annotation) reporters.

### `github.com/xraph/sentinel/sentineltest`

`Assert` with `MinPassRate`, `MinAverageScore`, `MaxLatency`, `MaxCost`, `NoRegressions`, and the dimension checks `SkillProficiency`, `TraitConsistency`, `BehaviorTriggerRate`, `CognitivePhaseCompliance`, `CommunicationMatch` and `PersonaCoherence`. `NoRegressions` fails when any case failed; it doesn't compare against a baseline.

## Store packages

### `github.com/xraph/sentinel/store`

The composite `Store` interface.

### `store/postgres`, `store/sqlite`, `store/mongo`

`New(db *grove.DB)` for each, plus its `Migrations` group. Call `Migrate` before first use. SQLite needs the `sqlitemigrate` blank import; see [SQLite](/docs/infrastructure/sqlite).

### `store/memory`

`New()`, for tests and throwaway runs.

### `store/storetest`

`Run(t, factory)`, the conformance suite.

## Infrastructure packages

### `github.com/xraph/sentinel/plugin`

`Extension` and the 15 hook interfaces, plus the `Registry`.

### `github.com/xraph/sentinel/observability`

```go
func NewMetricsExtension() *MetricsExtension
func NewMetricsExtensionWithFactory(factory gu.MetricFactory) *MetricsExtension
```

### `github.com/xraph/sentinel/audit_hook`

Package `audithook`: `New(recorder, ...Option)`, `Recorder`, `RecorderFunc`, `AuditEvent`, `WithActions`, `WithLogger`, and the action, severity and outcome constants.

### `github.com/xraph/sentinel/api`

Forge HTTP handlers. `New(eng, router)` creates the API, `RegisterRoutes(router)` mounts the routes under `/v1`, `Handler()` returns an `http.Handler`. Many routes don't register yet; see the [HTTP API reference](/docs/api-reference/http-api).

### `github.com/xraph/sentinel/extension`

The Forge extension. `New(...ExtOption)` creates it; `Config`, `DefaultConfig()` and the `With...` options configure it. See the [Forge guide](/docs/guides/forge-extension).

## ID package

### `github.com/xraph/sentinel/id`

```go
func NewSuiteID() SuiteID
func NewCaseID() CaseID
func NewEvalRunID() EvalRunID
func NewEvalResultID() EvalResultID
func NewBaselineID() BaselineID
func NewRedTeamID() RedTeamID
func NewPromptVersionID() PromptVersionID

func ParseSuiteID(s string) (SuiteID, error)
func ParseCaseID(s string) (CaseID, error)
func ParseEvalRunID(s string) (EvalRunID, error)
func ParseEvalResultID(s string) (EvalResultID, error)
func ParseBaselineID(s string) (BaselineID, error)
func ParseRedTeamID(s string) (RedTeamID, error)
func ParsePromptVersionID(s string) (PromptVersionID, error)
```

The typed names are aliases of `id.ID`, a TypeID on UUIDv7. All IDs have `String()`, and the nil ID prints as an empty string.
