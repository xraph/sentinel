---
title: HTTP API Reference
description: The REST routes in the api package, which of them work today, and what they take and return.
---

The `api` package holds Forge handlers for suites, cases, runs, baselines, prompt versions, red team, scenarios and reports. The Forge extension mounts them under `base_path` (default `/sentinel`) plus `/v1`, so every path below starts with `/sentinel/v1`. Without the extension, `api.New(eng, router).RegisterRoutes(router)` mounts them on a Forge router, and `Handler()` gives you an `http.Handler`. Authentication is whatever your Forge middleware does.

The API is partial. Against Forge v1.12.7, 18 of the 29 routes fail to register: Forge rejects handlers that return a slice, a map or `any`, and the `api` package discards the registration error. Those routes answer 404 (or 405 when another method shares the path). Of the 11 that do register, `POST /suites/:suiteId/runs` always answers 400. Every successful response also writes its JSON body twice, once from the handler and once from Forge, so a strict JSON client fails to parse it. Use the Go API or the dashboard for anything beyond reading single records.

The sections below describe what each handler does, so you know what to expect once the registration problem is fixed. A route marked as a stub would answer 400 even then.

## Suites

### `POST /suites`

Create a suite. The app comes from the request context (`sentinel.WithApp`), and an empty `model` gets the engine's `DefaultModel`.

```json
{
  "name": "support-answers",
  "description": "string",
  "system_prompt": "string",
  "model": "string",
  "temperature": 0,
  "persona_ref": "string",
  "metadata": {}
}
```

`201 Created` with the suite. A duplicate name in the same app is `400` on the memory store and `500` on the SQL and Mongo stores.

### `GET /suites/:suiteId`

`200 OK` with the suite, or `404`.

### `PUT /suites/:suiteId`

Takes the same body as create and overwrites `name`, `description`, `system_prompt`, `model`, `temperature` and `persona_ref` with what you send, so send them all. `metadata` is replaced only when present. `200 OK` with the suite.

### `GET /suites` (not registered)

Would list suites for the request's app, with `limit` (default 50, max 1000) and `offset` query parameters.

### `DELETE /suites/:suiteId` (not registered)

Would delete the suite. The SQL stores cascade to its cases, runs, results, baselines and prompt versions. `204 No Content`.

## Cases

### `GET /cases/:caseId`

`200 OK` with the case, or `404`.

### `POST /suites/:suiteId/cases` (not registered)

Would create cases in a batch. `scenario_type` defaults to `standard`.

```json
{
  "cases": [
    {
      "name": "refund-window",
      "input": "How long do I have to ask for a refund?",
      "expected": "30 days",
      "scenario_type": "standard",
      "scorers": [{"name": "contains", "config": {"substring": "30 days"}}],
      "tags": ["refunds"],
      "context": {},
      "metadata": {}
    }
  ]
}
```

### `POST /suites/:suiteId/cases/import` (not registered)

Would import cases through `engine.ImportCases`. The data goes in a JSON body, not as a raw file:

```json
{ "format": "jsonl", "data": "{\"name\":\"a\",\"input\":\"hi\"}\n" }
```

`format` is `json`, `csv` or `jsonl`. Every row needs a name and an input, or nothing is written. `201 Created` with `{"imported": n}`.

### `GET /suites/:suiteId/cases`, `DELETE /cases/:caseId` (not registered)

Would list a suite's cases, and delete one case (`204`).

## Runs

### `POST /suites/:suiteId/runs`

Registered, but the handler builds a `RunConfig` with no target and no scorers, so `RunEval` refuses it and you always get:

```json
{"code":400,"error":"sentinel: no target configured"}
```

The body fields (`model`, `persona_ref`, `scorers`, `tags`, `concurrency`) are read but can't make it work. Start runs with `eng.RunEval` or `eng.StartRun` from Go, or from the dashboard, which starts runs against targets you registered with `WithTarget`.

### `GET /runs/:runId`

`200 OK` with the run, or `404`.

### `GET /runs/:runId/stats`

`200 OK` with the run's aggregates:

```json
{
  "total_cases": 50,
  "passed": 45,
  "failed": 3,
  "errored": 2,
  "pass_rate": 0.9,
  "avg_score": 0.87,
  "avg_latency_ms": 1200,
  "total_tokens": 50000,
  "total_cost": 2.50,
  "dimension_scores": {"skill": 0.92, "trait": 0.88}
}
```

### `GET /suites/:suiteId/runs`, `GET /runs/:runId/results` (not registered)

Would list a suite's runs (`state`, `limit`, `offset` query parameters) and a run's results.

### `POST /suites/:suiteId/compare` (stub, not registered)

The handler always answers 400 ("model comparison must be configured programmatically with target adapters"). Use `comparison.Compare` from Go.

## Baselines

### `POST /suites/:suiteId/baselines`

Save a stored run as the suite's current baseline. The handler copies the run's pass rate, average score, dimension scores and per-case results.

```json
{ "run_id": "erun_01h455vb...", "name": "v1" }
```

`201 Created` with the baseline. A bad `run_id` is `400`, an unknown one `404`.

### `GET /baselines/:baselineId`

`200 OK` with the baseline, or `404`.

### `GET /suites/:suiteId/baselines` (not registered)

Would list the suite's baselines.

### `POST /suites/:suiteId/runs/with-baseline` (stub, not registered)

The handler always answers 400. Every completed run is compared with the current baseline anyway.

## Prompt versions

### `POST /suites/:suiteId/prompts`

Create the suite's next prompt version. The engine numbers it.

```json
{ "system_prompt": "You are the support assistant for Acme.", "label": "shorter answers" }
```

`label` is stored as the version's `changelog`. The new version isn't made current, and the route that would do that isn't registered, so call `eng.SetCurrentPromptVersion` from Go. `201 Created` with the version.

### `GET /suites/:suiteId/prompts`, `POST /suites/:suiteId/prompts/current` (not registered)

Would list versions, and make one current with `{"version_id": "pver_..."}` (`204`).

## Red team and scenarios (stubs, not registered)

`POST /suites/:suiteId/redteam/generate`, `/redteam/run` and `/scenarios/generate` always answer 400 in the handler. Use `eng.GenerateRedTeam` and the `scenario` generators from Go. `GET /suites/:suiteId/scenarios` would list the suite's cases whose scenario type isn't `standard`.

## Reports

### `GET /runs/:runId/report`

`200 OK` with a JSON report: the run, its results, its stats and a generation time.

### `POST /runs/:runId/report/export` (not registered)

Would render the report with `{"format": "terminal" | "json" | "html" | "ci"}` (default `json`) and return it with a matching content type.

## Errors

Errors use Forge's error response, a JSON object with `code` and `error`:

| HTTP status | Cause |
|-------------|-------|
| `400` | An ID that doesn't parse, `ErrSuiteAlreadyExists`, `ErrInvalidState`, `ErrEmptyInput`, `ErrNoTarget`, `ErrNoScorers`, `ErrInvalidInput`, `ErrUnsupportedFormat`, and the stubs |
| `404` | Suite, case, run, baseline or prompt version not found, and unregistered routes |
| `500` | Anything else: a store error, or a unique-index violation on the SQL stores |
